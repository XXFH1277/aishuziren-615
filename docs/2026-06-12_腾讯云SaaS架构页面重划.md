# 腾讯云 SaaS 架构页面重划（留 / 砍 / 冻结）

> 本文是 2026-06-12 的产品架构方向重划，用于把现有"单租户 + 本地执行端 / OBS"原型，调整为"面向中小商家 / 主播的云 SaaS + 腾讯云数智人"产品。
>
> ⚠️ 本文结论与 `05_重新开发阶段路线图.md`、`docs/下一阶段开发建议.md` 中的 OBS / 执行端方向**冲突，以本文为准**：原 Phase 16（OBS WebSocket 对接）、Phase 20（执行端通信）、Phase 21（OBS 连接）相关方向**冻结**。

## 一、背景与关键决策

产品终局已明确：

1. **形态 = SaaS（订阅制）**，卖给中小商家 / 主播，不是私有化企业中控。
2. **数字人能力 = 外包给腾讯云数智人**（不自建渲染 / 口型 / TTS / 推流）。参考 [腾讯云智能数智人 IVH](https://cloud.tencent.com/product/ivh)。
3. **能力档位 = A 真·实时交互数智人**（腾讯云交互版），并以 **B 预生成视频循环作为冷场兜底**（hybrid 混合档）：
   - 有观众 / 评论时 → 实时交互驱动，真回评论；
   - 冷场 / 深夜无人时 → 预生成循环，降低边际成本。
4. 因此**没有本地执行端、没有 OBS、没有直播电脑**：数字人在腾讯云跑、从腾讯云直播推流。后端职责从"控制一台本地机器"转为"**编排腾讯云 + 管多租户 + 计量计费**"。

## 二、关键结构认知：需要"两个后台"

现有 ~44 个页面几乎全是"单租户管理后台"。SaaS 实际要拆成两套，下表用 `〔商家端〕`/`〔平台端〕`/`〔两端〕` 标注归属：

- **〔商家端〕商家自助后台**：商家登录，自己配商品 / 话术 / 数字人 / 直播间，看自己的中控台。
- **〔平台端〕运营后台**：管所有租户、套餐、计费、全局成本（腾讯总账）、全局合规、封号风控。**当前基本为空，是最大缺口。**

## 三、图例

- 🔧 **改**：保留但需按新架构改造。

## 四、逐模块处置

### 首页
- 首页工作台 Dashboard — 🔧改〔商家端〕P1：改成商家业务视角（我的直播间状态、今日数字人时长=成本、销售 / 互动、额度剩余告警）。

### 商品管理（核心，几乎全留）
- 商品列表 / 创建 / 编辑 — ✅留〔商家端〕**P0**。
- 商品组 — ✅留〔商家端〕P1。
- AI 商品文案 — 🔧改〔商家端〕**P0**：接**真实 LLM**（不再 fake provider），生成可直接喂数字人的话术。

### 数字人管理（概念整体替换）
- 数字人列表 — 🔧改〔商家端〕**P0**：从"本地数字人"改成"**我绑定的腾讯云形象**列表"。
- 创建数字人 — 🔧大改〔商家端〕**P0**：本地"创建"取消，换成**形象采购 / 复刻接入流程**（上传真人视频 → 送腾讯复刻 → 绑定）。
- 编辑数字人 — 🔧改〔商家端〕P1。
- 动作库 ActionLibrary — ❄️冻结：动作由腾讯形象侧定义，除非腾讯开放动作控制。

### 直播管理
- 直播间列表 — ✅留〔商家端〕**P0**。
- 创建 / 编辑直播间 — 🔧改〔商家端〕**P0**：删"绑执行端"；改成"**绑腾讯云形象 + 填平台推流地址（RTMP，商家自己抖音 / 快手直播间的推流串）**"。
- 直播任务 LiveTasks — ✅留〔商家端〕P1：排期 / 定时开播，24h 无人直播需要。
- 直播中控台 LiveControlRoom — 🔧升级〔商家端〕**P0**：实时监看 + 人工接管 + **实时 / 预生成一键切换**（hybrid 操作面）。走 A 这条路它价值最大。

### 实时互动（A 的关键路径）
- 弹幕捕获 CommentCapture — 🔧换真实数据源〔商家端〕**P0**：接真实弹幕驱动实时回复。⚠️ 抖音 / 快手无合法稳定接入，是 A 最大风险点，需先定授权方案。
- 问题队列 QuestionQueue — ✅留〔商家端〕P1。
- 人工接管 ManualTakeover — ✅留〔商家端〕**P0**：已有合规拦截，复用。

### 延迟播控（喂给腾讯的文本流，全留）
- 当前播报 CurrentSpeech — 🔧改〔商家端〕P1：显示腾讯数智人当前在播话术。
- 待播队列 SpeechQueue — ✅留〔商家端〕**P0**：喂腾讯的文本队列 + 下发前合规复检（已实现）。
- 字幕预览 SubtitlePreview — ✅留 / 简化〔商家端〕P2。
- 播控设置 DelaySettings — 🔧改〔商家端〕P1：加"**实时 ↔ 预生成切换阈值**"（hybrid 控制，如"有评论时切实时"）。

### AI 能力中心
- AI 助理设置 AiAssistant — ✅留〔商家端〕P2。
- 模型服务配置 ModelServices — 🔧改〔两端〕P1：配 LLM 凭证 + **腾讯数智人凭证**（平台端管密钥，商家端只见脱敏）。
- Prompt 模板 PromptTemplates — ✅留〔商家端〕P1。
- 合规词库 ComplianceCenter — 🔧分两层〔两端〕**P0**：**平台全局词库 + 商家自定义词库**。监管收紧，更重要。
- 调用日志 AiCallLogs — ✅留〔两端〕P2。
- 成本监控 AiCostMonitor — 🔧升级为重点〔两端〕**P0**：盯**腾讯实时数智人分钟费 + LLM 费**，直接决定毛利。平台端看总账，商家端看自己额度。

### 执行端管理（云端路线整组冻结）
- 执行端列表 / OBS 连接状态 / 心跳日志 — ❄️全冻结。未来可改造为"**腾讯云数智人实例状态**"监控再启用；现在不碰（除非还卖私有化）。

### 直播间搭建 studio
- OBS 输出 StudioOutput — ❌砍：OBS 没了。
- AI 生成背景 StudioBackground / 画面布局 StudioLayout — ❄️冻结：看腾讯数智人是否开放背景 / 布局配置，开放了再做成配置透传。

### 帮助中心（SaaS 必备，低优先，基本留）
- FAQ / 快速排查 / 教程 / 更新日志 — ✅留〔商家端〕P2。
- 技术工单 Tickets — ✅留〔两端〕P2：已有附件上传，复用。
- 系统状态 SystemStatus — 🔧改〔两端〕P2：加"腾讯云依赖状态"。

### 系统设置（多租户化是重点）
- 用户管理 UserManagement — 🔧改〔两端〕P1：拆成"**平台管租户**"和"**租户管自己的员工子账号**"。
- 角色权限 RolePermissions — 🔧降级简化〔商家端〕P2：小商家只要"管理员 / 员工"两档，复杂权限配置先冻结。

## 五、必须新增的承重墙（现在一页都没有）

| 新增页面 | 归属 | 优先级 | 作用 |
|---|---|---|---|
| 租户（商家）管理 | 平台端 | **P0** | 开通 / 停用 / 查看每个商家 |
| 套餐 & 订阅管理 | 平台端 | **P0** | 定价档、订阅、续费、停服 |
| 用量计量 & 账单 | 平台端 | **P0** | 腾讯分钟数 / LLM token 按租户计量、出账、额度告警 |
| 形象采购 / 接入 | 商家端 | **P0** | 真人视频 → 腾讯复刻 → 绑定（也可并进数字人管理） |
| 平台推流配置 | 商家端 | **P0** | 商家填自己平台直播间的 RTMP 推流地址 |
| 全局成本总账 | 平台端 | P1 | 盯"腾讯花了多少 vs 收了多少" |

## 六、MVP 第一刀（P0 闭环）

> 商品录入 → AI 真实话术 → 绑腾讯形象 → 配直播间 + 推流地址 → 中控台（实时 / 预生成切换 + 接管） → 待播队列（喂文本 + 合规） → 弹幕接入 → 成本监控 → 多租户 + 计费骨架。

其余 P1 / P2 往后排，执行端 / OBS / studio 直接冻结。开发量从"50 个页面"砍到**十几个真正决定生死的页面**，且每个都接真发动机、都服务于"商家月付能否覆盖腾讯成本"。

## 七、写代码前必须先定的三个风险

1. **成本账**：腾讯实时按"并发 × 分钟"持续计费，外加形象采购 + 交互服务。需先问到报价，算清"一个商家月付 vs 腾讯月成本"，否则毛利可能为负。
2. **弹幕合规接入**：抖音 / 快手 / 视频号 / 淘宝无合法稳定的开源弹幕接入，仅 B 站有官方开放平台。A 的实时互动落在这条关键路径上，需官方 / ISV 授权或承担封号风险。
3. **平台监管**：数字人 / 无人直播合规要求收紧（AI 标识、部分类目限制）。作为 SaaS 服务商，需替商家承担聚合风险。
