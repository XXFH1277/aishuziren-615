# 接口预留设计补充

状态：设计预留文档，部分先返回 Mock，不要求立即实现
适用前端：当前 React + Vite 后台原型
目标后端：本地 Node + Express + SQLite，逐步真实化
关联文档：`docs/API接口设计.md`、`docs/当前系统能力边界.md`、`docs/下一阶段开发建议.md`

## 0. 本文档目的

`docs/API接口设计.md` 已覆盖实体 CRUD。本文件补充“系统级”接口，这些接口后期补会引发数据结构和前端数据流返工，因此建议**现在就冻结契约**（哪怕先返回 Mock）。

实现优先级标记：

- P0：建议现在就冻结契约
- P1：建议补，但不紧急
- 字段预留：成本最低、收益最高，应立即在表结构中预留

## 1. 字段预留（立即执行，几乎零成本）

在核心表（products / avatars / live_rooms / live_tasks / executors 等）预留以下列，即使当前单租户、不软删除也先留空：

- `tenant_id`：多租户预留，单租户先填固定值。
- `platform_account_id`：平台账号关联预留。
- `deleted_at`：软删除标记，空表示未删除。

理由：后补列需要数据迁移，提前留近乎零成本。

## 2. 实时通道消息契约（P0）

当前弹幕、待播队列、心跳、中控台状态全靠前端轮询。先冻结消息格式，避免接平台弹幕时前端重写。

统一消息信封：

```json
{
  "type": "comment.new",
  "msgId": "MSG_xxx",
  "ts": "2026-05-29 10:00:00",
  "liveTaskId": "LT001",
  "payload": {}
}
```

约定：

- 增量拉取兜底（WebSocket 不可用时降级轮询）：`GET /api/realtime/poll?sinceId=MSG_xxx&channel=comment`
- 客户端去重依据 `msgId`，顺序依据 `ts`，重连用 `sinceId` 续传。
- 频道枚举：`comment`（弹幕流）、`speech-queue`（待播队列变化）、`executor-heartbeat`（心跳）、`console-status`（中控台状态）。

## 3. 执行端通信协议（P0，最易返工）

| 接口 | 方法 | 路径 | 说明 | 关键约定 |
| --- | --- | --- | --- | --- |
| 注册 | POST | `/api/executors/register` | 执行端首次上线注册 | 返回 `executorId` + 绑定状态 |
| 绑定 | POST | `/api/executors/bind` | 用绑定码绑定到账号 | Body: `bindCode` |
| 心跳 | POST | `/api/executors/:id/heartbeat` | 周期上报在线状态 | Body: `status`, `obsStatus`, `metrics` |
| 命令下发 | POST | `/api/executors/:id/commands` | 后台向执行端下发命令 | **必须带 `idempotencyKey`、`timeoutMs`** |
| 命令回执 | POST | `/api/executors/:id/commands/:cmdId/ack` | 执行端回报命令结果 | Body: `status`, `result`, `errorMessage` |
| 解绑 | POST | `/api/executors/:id/unbind` | 解除绑定 | 需权限校验 |

强约定：命令下发必须幂等（同一 `idempotencyKey` 重复下发不重复执行）、有超时与重试语义、回执包含失败原因。这是真实化中最易推翻重做的部分。

## 4. 异步任务中心（P0）

数字人训练、声音克隆、口型同步、批量文案均为长耗时操作，不能用同步请求。统一任务模型：

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 创建任务 | POST | `/api/jobs` | Body: `type`(`avatar_train`/`voice_clone`/`lip_sync`/`batch_copy`), `params` |
| 查询任务 | GET | `/api/jobs/:id` | 返回 `status`(`pending`/`running`/`succeeded`/`failed`), `progress`, `result`, `error` |
| 任务列表 | GET | `/api/jobs` | Query: `type`, `status`, `page`, `pageSize` |
| 任务回调 | POST | `/api/jobs/:id/callback` | 供异步执行方回写结果，需验签 |

配套：AI 长文案/批量生成应走 job，而非现有同步 `/api/ai/generate`。

## 5. AI 流式输出（P1）

商品口播、长文案场景预留 SSE：

- `POST /api/ai/generate/stream`，`Content-Type: text/event-stream`，按 token 推送 `data: {...}`。
- 仍复用 `providerGuardrails` 守卫；流式过程也要受频率/费用保护。

## 6. 平台对接入口（P0 预留契约）

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 平台授权回调 | GET | `/api/platforms/:platform/oauth/callback` | OAuth 回调，换取平台 token（后端保存，不下发前端） |
| 平台事件 webhook | POST | `/api/platforms/:platform/events` | 接收平台推送（弹幕、订单、状态），需验签 |
| 订单/GMV 回流 | GET | `/api/platforms/:platform/orders` | 拉取订单用于复盘 |

`platform` 枚举：`douyin` / `kuaishou` / `wechat-channels` / `xiaohongshu` / `taobao`。

## 7. 统一 Webhook 接收入口（P0）

支付、平台事件、模型异步结果统一从验签入口进：

- `POST /api/webhooks/:source`，`source` 枚举：`payment` / `platform` / `ai-job`。
- 统一验签、幂等（按事件 id 去重）、入库后再异步处理。

## 8. 全局合规/敏感词中心（P0，业务高风险）

当前 `forbiddenExpressions` 内嵌在商品里，应升级为“全局词库 + 商品级覆盖”两层。

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 词库列表 | GET | `/api/compliance/keywords` | Query: `riskLevel`, `category`, `keyword` |
| 新增/更新词条 | POST/PUT | `/api/compliance/keywords[/:id]` | `text`, `riskLevel`, `action`(`block`/`rewrite`/`warn`) |
| 合规检查 | POST | `/api/compliance/check` | Body: `text` → 返回命中词、风险等级、建议动作 |

与延迟播控“人工确认”打通：命中高风险即拦截或强制人工复核。

## 9. 复盘 / 数据分析（P1）

- `GET /api/analytics/live-review?liveTaskId=` ：单场复盘（时间线、待播命中率、人工接管点、风险拦截数、GMV/转化）。
- `GET /api/analytics/overview?dateRange=` ：跨场聚合。

## 10. 审计日志查询（P1）

后端已有 `server/utils/operationLog.js`，补对外查询：

- `GET /api/audit/logs`：Query `userId`, `module`, `action`, `startTime`, `endTime`, `page`, `pageSize`。

## 11. 文件能力补全（P1）

- `DELETE /api/files/:id`：删除文件资产。
- `GET /api/files/:id/signed-url`：为云存储过渡预留签名 URL。

## 12. 告警 / 通知下发（P1）

- `GET /api/notifications`：站内通知列表。
- 触发源：预算超限、执行端离线、高风险弹幕。先入库，实时推送复用第 2 节通道。

## 13. 落地建议

- 第 1 节字段预留：随下一次表结构变更一并加入。
- 第 2、3、4、6、7、8 节（P0）：先建路由并返回 Mock，把契约写进 `docs/API接口设计.md` 主表，前端按契约对接，后端逐步替换实现。
- 其余 P1：按 `docs/下一阶段开发建议.md` 的 Phase 排期推进。
- 所有真实化接口必须沿用现有守卫习惯：先 Mock/Fake，再切真实；密钥只后端持有、脱敏、限流、费用保护、审计。
