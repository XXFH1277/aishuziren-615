# 2026-06-05 直播中控台接入真实待播下发交接

## 1. 本次目标

把直播中控台右侧播控区接入已完成的真实待播队列下发链路，让运营可以在 `/live/control-room` 直接触发 `speech_queue` 下发，而不必切换到 `/delay-control/queue`。

本次复用现有接口：

```text
GET  /api/delay-control/current
GET  /api/delay-control/queue
POST /api/delay-control/queue/:id/dispatch
POST /api/delay-control/queue/dispatch-next
```

未新增后端接口，未改变执行端安全收口和下发状态机。

## 2. 前端改动

修改页面：

```text
src/pages/live/LiveControlRoom.jsx
```

主要变化：

- 初次加载中控台时，同时读取当前直播任务对应的真实 `speech_queue`。
- 右侧“固定播控区”展示：
  - 当前下发中
  - 下一条待下发
  - 后续队列
  - 最近已播报
- 增加“下发下一条”按钮，调用 `dispatchNextSpeechItem({ liveTaskId })`。
- 增加单条“下发播报”按钮，调用 `dispatchSpeechItem(id, { liveTaskId })`。
- 下发成功后刷新右侧队列状态。
- 显示 `broadcastStatus`、`executorCommandId`、失败原因等真实状态字段。
- 对执行端未绑定、执行端离线/异常、无可下发话术提供禁用态和提示。

## 3. Service 复用

继续复用：

```text
src/services/delayControlService.js
```

使用函数：

```text
getCurrentSpeech(params)
getSpeechQueue(params)
dispatchSpeechItem(id, data)
dispatchNextSpeechItem(data)
```

页面没有直接 `fetch`，仍走统一 `request`。

## 4. 当前链路

```text
直播中控台右侧播控区
→ delayControlService
→ /api/delay-control/queue/:id/dispatch
→ server/routes/delayControl.js
→ executor_commands 写入 speak
→ executor-client PrintAdapter 拉取并回执
→ server/routes/executors.js ack
→ speech_queue 回写 已播报 / 失败
→ 直播中控台刷新展示
```
