# 2026-06-05 本地执行端客户端 MVP 交接

## 1. 本次目标

本次完成执行端通信协议的本地 Node CLI 客户端 MVP，并把后台执行端页面的“生成绑定码”入口接到真实后端接口。

目标链路：

```text
后台生成绑定码
→ executor-client 用绑定码注册
→ 后端返回 deviceToken
→ executor-client 本地保存 deviceToken
→ executor-client 周期性上报心跳
→ executor-client 轮询待执行命令
→ executor-client 打印命令并回执
→ 后台执行端列表可看到最新命令状态
```

## 2. 新增内容

### executor-client

新增独立目录：

```text
executor-client/
├── package.json
├── README.md
├── config.example.json
└── src/
    └── index.js
```

当前客户端特点：

- 不参与前端 Vite 构建。
- 使用 Node 原生 `fetch`，不新增 axios 或客户端依赖。
- 从环境变量或 `executor-client/config.local.json` 读取 `baseUrl`、`bindCode`、心跳间隔和请求超时。
- 首次启动时调用 `POST /api/executors/register`，用绑定码换取 `deviceToken`。
- 将 `deviceToken` 保存到 `executor-client/.device.json`。
- 后续启动时复用本地 `deviceToken`，不重复注册。
- 使用 Node `os` 模块采集 CPU、内存、系统类型、主机名等本地指标。
- 周期性调用 `POST /api/executors/:id/heartbeat` 上报心跳。
- 周期性调用 `GET /api/executors/:id/commands/pending` 拉取命令。
- 对已处理命令做本地幂等记录，避免同一 commandId 重复执行。
- MVP 阶段命令只打印并回执，不执行真实 OBS、虚拟摄像头、数字人播报或推流。
- 后端不可达、网络超时、device token 失效时会打印清晰错误并退避重试，不直接崩溃退出。

## 4. 本地运行说明

### 后端

```bash
npm run server:seed
npm run server:dev
```

### 前端

```bash
npm run dev
```

在执行端列表页生成绑定码。

### 执行端客户端

方式一：环境变量。

```bash
cd executor-client
BIND_CODE=BIND-XXXXYYYY npm start
```

Windows PowerShell 可使用：

```powershell
$env:BIND_CODE="BIND-XXXXYYYY"
npm start
```

方式二：本地配置文件。

```json
{
  "baseUrl": "http://localhost:3000",
  "bindCode": "BIND-XXXXYYYY",
  "heartbeatIntervalSeconds": 10,
  "requestTimeoutMs": 8000
}
```

保存为：

```text
executor-client/config.local.json
```

## 5. 验收链路

端到端验收步骤：

1. 启动后端。
2. 启动前端并登录。
3. 进入执行端管理 / 执行端列表。
4. 点击“生成绑定码”。
5. 使用该绑定码启动 `executor-client`。
6. 客户端注册成功后，本地生成 `.device.json`。
7. 执行端列表刷新后能看到新设备上线，最后心跳持续更新。
8. 对该设备点击“重启”，后端写入待执行命令。
9. 客户端轮询到命令并打印。
10. 客户端调用回执接口，命令状态更新为 succeeded。
11. 前端刷新列表后可看到最近命令状态为已完成。
