# 2026-06-05 直播中控台人工接管入队与直发交接

## 1. 本次目标

把直播中控台“人工接管”输入接入两种可验证链路：

```text
加入待播队列：人工输入 → speech_queue(source=manual_takeover) → 右侧播控区后续下发
立即播报：人工输入 → speech_queue → speak 命令 → 执行端 PrintAdapter → ack → speech_queue 状态回写
```

本次仍不接真实 DUIX、TTS、口型同步、推流或直播平台。

## 2. 后端改动

修改文件：

```text
server/routes/liveControlRoom.js
```

### 2.1 入队模式

`POST /api/live/control-room/manual-speech`

请求体使用：

```json
{
  "taskId": "LT001",
  "text": "人工接管话术",
  "tone": "专业",
  "action": "看评论区",
  "deliveryMode": "queue"
}
```

行为：

- 写入 `speech_queue`
- `source = manual_takeover`
- 默认 `review_status = 已通过`
- `broadcast_status = 待下发`
- 返回 `speechItem`

### 2.2 直发模式

`POST /api/live/control-room/manual-speech`

请求体使用：

```json
{
  "taskId": "LT001",
  "text": "人工接管话术",
  "tone": "热情",
  "action": "微笑回应",
  "deliveryMode": "direct"
}
```

行为：

1. 写入 `speech_queue`。
2. 校验当前直播任务是否绑定执行端。
3. 校验执行端状态是否在线。
4. 写入 `executor_commands`，`command_type = speak`。
5. payload 带 `speechQueueId / liveTaskId / liveRoomId / text / tone / source`。
6. 将队列项置为 `broadcast_status = 下发中`。
7. 执行端 ack 后复用已有逻辑回写 `speech_queue` 为 `已播报` 或 `失败`。

### 2.3 兼容说明

未传 `deliveryMode` 时，接口保留旧的 Mock 接收/建议行为，避免破坏已有页面和 smoke 兼容用例。

## 3. 前端改动

修改文件：

```text
src/services/liveControlRoomService.js
src/pages/live/LiveControlRoom.jsx
```

新增 service：

```text
enqueueControlRoomManualSpeech(data)
directSpeakControlRoomManualSpeech(data)
```

人工接管区改为：

- “加入待播队列”：调用入队模式，成功后刷新右侧播控区。
- “立即播报”：调用直发模式，成功后刷新右侧播控区。
- “立即播报”在执行端未绑定、离线或异常时禁用。
- 保留“仅生成建议 Mock”作为轻量占位。

## 4. Smoke Test

新增覆盖：

1. 人工接管入队，确认 `source = manual_takeover` 且 `broadcastStatus = 待下发`。
2. 人工接管直发，确认返回 `commandId` 且队列项进入 `下发中`。
3. 执行端拉取直发 `speak` 命令。
4. 执行端 ack 后，确认对应 `speech_queue` 回写为 `已播报`。
