# 前后端数据契约说明

Phase：11  
状态：契约设计，不接真实后端  

## 1. 目标

当前前端已经完成：

```text
页面组件
↓
Service 层
↓
Mock 数据
```

后续接入后端时，目标结构调整为：

```text
页面组件
↓
Service 层
↓
HTTP API
↓
Node 后端
↓
SQLite / AI代理 / 本地执行端
```

因此数据契约的核心目标是：后续只替换 `src/services/*.js` 的内部实现，尽量不改页面组件。

## 2. 命名约定

### 前端字段

- 使用 camelCase。
- 示例：`productGroupName`、`updatedAt`、`riskLevel`、`liveRoomId`。

### 后端数据库字段

- 使用 snake_case。
- 示例：`product_group_name`、`updated_at`、`risk_level`、`live_room_id`。

### API 返回字段

- 面向前端返回 camelCase。
- 后端查询数据库后负责转换 snake_case -> camelCase。

示例：

```json
{
  "id": "LR001",
  "liveRoomName": "舟山海鲜礼盒晚场",
  "productGroupName": "舟山特产组",
  "updatedAt": "2026-05-26 20:00"
}
```

## 3. 通用响应结构

所有 API 统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
```

## 4. 登录与权限

Phase 13 已完成本地 Auth / RBAC MVP。

当前约定：

- `/api/auth/login` 校验 SQLite 用户密码 hash，成功后返回 Bearer token。
- 后端 `auth_sessions` 只保存 token hash，不保存明文 token。
- 前端只在本地保存后端返回的 token，不保存密码，不把 token 写入代码仓库。
- 系统设置等少量接口已示范强制登录和权限 key 校验。
- RBAC 权限基于 Phase 10 的角色权限结构：
  - 菜单权限：控制侧边栏和路由可见性。
  - 操作权限：控制新增、编辑、删除、审核、导出、启动任务、人工接管。
  - 数据权限：全部 / 本人 / 所属团队 / 只读。

生产级登录仍需后续补充 HttpOnly Cookie / CSRF 策略、登录限流、密码重置、多端会话管理和全量接口权限校验。

未登录：

```json
{
  "code": 40101,
  "message": "请先登录",
  "error": null
}
```

无权限：

```json
{
  "code": 40301,
  "message": "当前角色没有该操作权限",
  "error": null
}
```

## 5. 分页、搜索和筛选

通用 Query：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| page | number | 1 | 当前页 |
| pageSize | number | 20 | 每页数量 |
| keyword | string | 空 | 搜索关键词 |
| status | string | 空 | 状态筛选 |
| startTime | string | 空 | 开始时间 |
| endTime | string | 空 | 结束时间 |

约定：

- `page` 从 1 开始。
- `pageSize` 建议上限 100。
- 空字符串和未传参数都视为不筛选。
- 时间范围由后端校验 `startTime <= endTime`。

实时流接口不使用传统页码，统一使用：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| cursor | string | 游标，可为空 |
| sinceId | string | 只取某条记录之后的新数据 |
| limit | number | 返回数量，建议默认 30，上限 100 |

适用场景：

- 直播弹幕流
- 直播中控台弹幕流
- 执行端实时心跳预览
- 待播队列增量刷新

## 10. Service 层替换规则

当前写法示例：

```js
import { products } from '../mock/products';

export function getProducts() {
  return products;
}
```

后续替换为：

```js
import { request } from './request';

export async function getProducts(params) {
  const response = await request.get('/api/products', { params });
  return response.data.list;
}
```

迁移原则：

- 页面组件只调用 service，不直接调用 `fetch`。
- service 内部负责 HTTP 请求、字段转换、错误兜底。
- service 返回结构应尽量兼容当前页面使用方式。
- 如果需要异步化，页面再逐步补充 loading 和 error 状态。

## 13. 文件上传契约

Phase 14 已完成本地真实上传 MVP。

当前链路：

1. 前端上传到 `/api/files/upload`。
2. 后端保存到本地 `server/uploads/`。
3. 后端写入 `file_assets`。
4. API 返回文件元信息：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "file": {
      "fileId": "FILE001",
      "fileUrl": "/uploads/product/FILE001-mock-file.png",
      "fileName": "mock-file.png",
      "fileType": "image",
      "size": 102400,
      "mimeType": "image/png",
      "uploadedAt": "2026-05-26 23:30:00"
    },
    "mock": false
  }
}
```

当前边界：需要登录 token；单文件最大 5MB；允许 PNG、JPG、WEBP、GIF、PDF、TXT、MP4、WEBM、MOV、MP3、WAV、M4A、AAC；不接云存储、不做病毒扫描。

适用场景：

- 商品主图
- 数字人照片 / 声音 / 视频素材
- 数字人训练素材
- 数字人肖像 / 声音 / 商用授权文件
- 直播间背景素材
- 工单截图
- 系统 Logo

Phase 17 已接入的前端入口：

## 14. AI 模型安全契约

严禁：

- 前端读取 `模型api.txt`
- 前端读取 `.env.local`
- 前端保存真实 API Key
- 前端把 API Key 写入 localStorage、Mock、日志或交接记录

后续真实调用方式：

```text
前端
↓
/api/ai/generate
↓
后端读取安全配置
↓
Kimi / Mimo / DeepSeek / OpenAI 等模型服务
```

模型配置接口中，前端可以提交：

```json
{
  "provider": "Kimi",
  "baseUrl": "https://api.moonshot.ai/v1",
  "modelName": "kimi-k2.6",
  "maxTokens": 2048,
  "temperature": 0.7,
  "enabled": true
}
```

`PUT /api/ai/models/:id` 不接收明文 `apiKey`，只接收 baseUrl、modelName、maxTokens、temperature、enabled 等非密钥配置。

如未来需要配置密钥，必须单独设计：

```text
PUT /api/ai/models/:id/credentials
GET /api/ai/models/:id/credentials
DELETE /api/ai/models/:id/credentials
```

该接口只能由后端处理密钥写入或加密保存。

但 API Key 只能：

- 由后端环境变量读取，或
- 通过后端加密接口保存，且永不返回明文。

返回给前端只能是：

```json
{
  "apiKeyConfigured": true,
  "apiKeyMasked": "********",
  "credentialRef": "cred_kimi_default"
}
```

Phase 18A 当前约定：

- credentials 接口可以接收 fake key 做本地联调，但 SQLite 不保存明文 `apiKey`。
- `ai_model_credentials` 只保存 `credential_ref`、`api_key_masked`、`source`、`base_url`、`model_name`、`remark` 等非明文字段。
- `/api/ai/models/:id/test` 默认走 fake provider，真实 provider 即使传入 `realProvider=true` 也返回“当前阶段未开启真实模型调用”。
- fake provider 会写入 `ai_call_logs` 和 `ai_cost_daily`，只记录脱敏摘要、耗时、token、费用估算和错误类型。
- 前端模型配置页只展示 `apiKeyConfigured`、`apiKeyMasked`、`credentialRef`，不展示明文。

Phase 18B-1 `product_copy` 当前约定：

- `POST /api/ai/generate` 是统一生成入口，当前只支持 `scenario=product_copy`。
- 支持 `target=description | selling_points | live_script | faq | compliance_rewrite`。
- 后端优先读取 `productId` 对应 SQLite 商品，再用 `draftProduct` 覆盖草稿字段。
- 默认 `realProvider=false`，只走 fake provider；即使传入 `realProvider=true`，当前阶段也不调用真实模型。
- `ai_call_logs.input_summary` 只记录商品 id、target、字段数量和模板 id，不记录完整商品草稿。
- `ai_call_logs.output_summary` 只记录生成类型、长度和风险提醒数量，不记录完整敏感输出。

Phase 18B-2 AI provider guardrails 当前约定：

- `GET /api/ai/runtime-policy` 返回当前 AI 运行策略，用于前端展示 `fake_provider_only`、频率限制、单日调用上限、预算保护和密钥安全边界。
- `server/ai/providerGuardrails.js` 统一判断 `realProvider=true` 请求是否允许进入真实 provider 流程。
- 默认必须同时具备后端环境变量 `AI_REAL_PROVIDER_ENABLED=true` 与 `AI_REAL_PROVIDER_SAFETY_APPROVED=true`，并且模型凭证已配置、未超过单分钟调用上限、未超过单日调用上限、未超过单日预算，才会通过 guardrails。
- 当前阶段即使 guardrails 通过，`openaiCompatibleProvider` 仍保持框架占位，不默认发起外部模型调用。
- 默认情况下，模型连接测试和 `product_copy` 传入 `realProvider=true` 会返回 `blocked=true`、`guardrail.reason=real_provider_disabled`，并写入脱敏日志。
- guardrails 日志只记录拦截原因、耗时、token=0、cost=0 和脱敏摘要，不记录 API Key、Authorization header、完整 Prompt、完整商品草稿或完整模型输出。

`POST /api/ai/models/:id/test` 必须满足：

- 只由后端代理调用真实模型服务。
- 不记录完整 API Key。
- 不记录敏感 Prompt。
- 设置请求超时。
- 设置频率限制。
- 设置费用保护。
- 写入脱敏日志。

## 17. 前端错误处理约定

service 层建议统一处理：

- `40101`：跳转登录页或提示重新登录。
- `40301`：提示无权限。
- `40400`：页面显示 Empty 或友好错误。
- `40900`：提示当前状态不允许操作。
- `50000`：提示服务异常，建议查看帮助中心 / 快速排查。

页面层只负责：

- loading
- Empty
- message / Modal 反馈
- 表单错误展示

- File 已升级为本地真实上传 MVP：`fileService.uploadFile(data)` 对应 `POST /api/files/upload`。请求使用 `multipart/form-data`：`file`、`module`、`businessId`、`fileType`。
- `file_assets` 表记录本地上传文件元信息；不得写入真实云存储地址或敏感信息。

## Phase 15 工单附件契约补充

- 工单附件上传复用 `fileService.uploadFile()`，上传时使用 `module=ticket`、`businessId=new-ticket`、`fileType=document/image`。
- 新建工单时，前端将已上传文件的 `fileId` 通过 `attachmentIds` 传给 `POST /api/help/tickets`。
- 后端创建工单后写入 `ticket_attachments`，并把对应 `file_assets.business_id` 更新为新工单 ID。
- `GET /api/help/tickets` 返回的每条工单包含 `attachments` 数组，用于详情弹窗展示和打开本地 `/uploads/*` 文件。

当前不接真实外部工单系统，不发送邮件、短信或 IM 通知；工单回复和关闭仍为 Mock。
