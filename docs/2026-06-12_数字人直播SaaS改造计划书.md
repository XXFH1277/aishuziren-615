# 数字人直播带货 SaaS 改造计划书

> 本文是 2026-06-12 的总体改造计划书，统领产品方向、范围调整、交互改造与 API 接口设计（含 LLM 代理与腾讯数智人对接）。
>
> 配套文档：页面级留/砍/冻结详见 `docs/2026-06-12_腾讯云SaaS架构页面重划.md`。
>
> ⚠️ 本文优先级高于 `05_重新开发阶段路线图.md` 与 `docs/下一阶段开发建议.md` 中的 OBS/执行端方向：原 Phase 16（OBS WebSocket）、Phase 20（执行端通信）、Phase 21（OBS 连接）作废。

---

## 1. 背景与战略决策

| 决策项 | 结论 |
|---|---|
| 产品形态 | **SaaS（订阅制）**，面向中小商家 / 主播 |
| 数字人能力 | **外包给腾讯云智能数智人（IVH）**，不自建渲染/口型/TTS/推流 |
| 能力档位 | **A 真·实时交互数智人**（腾讯交互版）+ **B 预生成循环兜底**（hybrid：有互动时实时，冷场时循环） |
| 架构含义 | **无本地执行端、无 OBS、无直播电脑**；数字人在腾讯云跑、云端推流 |
| 后端职责 | 从"控制本地机器" → "**编排腾讯云 + 管多租户 + 计量计费**" |
| 话术/回复 | 后端 LLM 代理（OpenAI 兼容，Kimi/DeepSeek/通义），前端不接触密钥 |

---

## 2. 总体架构

```
商家浏览器/手机
   │  (1) 配商品/话术/形象/直播间、看中控台
   ▼
我们的后端 (Node + Express + SQLite/未来 PG)
   ├─ 多租户 + 鉴权 + 计费计量
   ├─ LLM 代理 (话术生成 / 弹幕回复) ──► Kimi / DeepSeek / 通义 (OpenAI 兼容)
   ├─ 合规引擎 (敏感词 + 后置检查)
   └─ 腾讯数智人适配层 ──► 腾讯 IVH (开播/驱动/插播/下播 + SEI 状态)
                                   └─► 腾讯云直播 ──► 商家平台直播间 (抖音/快手…)
```

两个后台（详见配套文档 §二）：**〔商家端〕自助后台** + **〔平台端〕运营后台**。

## 3. 范围调整（摘要）

- **留/改（P0 核心）**：商品、AI 话术、数字人(改为绑腾讯形象)、直播间(改为绑形象+平台推流地址)、中控台(按腾讯架构重构)、待播队列、弹幕接入、成本监控、合规。
- **冻结**：执行端管理（列表/OBS/心跳）、studio（OBS 输出/背景/布局）、动作库、复杂角色权限。
- **砍**：OBS 输出页。
- **新增承重墙**：多租户、套餐/订阅、用量计量/账单、形象采购接入、平台推流配置、平台运营端。

> 逐页字段级处置见 `docs/2026-06-12_腾讯云SaaS架构页面重划.md`。

## 4. 交互改造方向（三层）

1. **导航**：企业级深树（10 组~40 页）→ 小商家任务式浅导航（`开播 / 商品 / 数字人 / 直播间 / 互动 / 数据 / 设置`）。
2. **文案**：删除研发黑话（Mock/fake/PrintAdapter/执行端/OBS/DUIX/下发 speak），全部改"商家话"。
3. **交互模型**：从"人工逐句下发的专业中控" → "**AI 自动播 + 自动回评，人工兜底**"，并新增**开播向导**。

## 5. 首页工作台 · 商家版规格（实现级）

商家首页 3 秒回答：**在播吗？卖了吗？还够播吗？有没有急事？**

**横幅状态机**（优先级）：`error > live > 新手未完成 > idle`。

**今日经营 4 卡**：今日成交(¥+涨跌) / 今日观看(人) / 今日直播时长 / **套餐额度剩余(分钟, 告警+续费)**。
**我的直播间**（状态徽标 + 进中控/去配置）｜**待我处理**（可操作，非日志）｜**快捷开始**｜**新手 4 步清单**。

**首页删除**：在线执行端、模拟弹幕数、模型调用状态、最近操作记录。

接口：`GET /api/merchant/home/overview`（按 token 锁租户），`data` 含 `merchant/live{state,current,last}/stats/rooms/todos/onboarding`。`〔平台〕`来源指标(观看/成交)不可用时显示"接入中"，绝不显示假数字。

> 字段/空态/移动端单列/文案对照表的完整细节，已在交互规格中定稿，落地时按此实现。

## 6. API 接口设计 ★

### 6.1 通用约定

- **响应**：沿用现有 `{ code, message, data }`，`code=0` 成功；分页用 `page()`。
- **鉴权**：Bearer token；`/api/*` 默认 `requireAuth`，写操作 `requirePermission`。
- **多租户**：每请求由 token 解析 `tenantId`，所有查询/写入按 `tenant_id` 隔离。
- **密钥安全**：LLM key、腾讯 appkey/secret **只在后端**，前端永不接触；沿用 `providerGuardrails` 脱敏与审计。

### 6.2 LLM 代理接口（基于现有 `/api/ai/generate` 扩展为真实 provider）

| 接口 | 用途 | 入参 | 出参 |
|---|---|---|---|
| `POST /api/ai/generate` | 商品文案/话术/FAQ/合规改写 | `{ scene:'product_copy', target, productId|draftProduct, input }` | `{ text, riskTips, compliance, usage{tokens,cost} }` |
| `POST /api/ai/comment-reply` | 弹幕实时回复（低延迟） | `{ liveSessionId, comment, context }` | `{ reply, riskLevel, action }` |
| `GET /api/ai/models` | 列出/状态（脱敏） | — | 模型与配置状态 |
| `PUT /api/ai/models/:id/credentials` | 配密钥（仅后端存） | `{ apiKey, baseUrl }` | 脱敏状态 |
| `POST /api/ai/models/:id/test` | 后端代理测试连接 | — | `{ ok, latency }` |

- **Provider 适配**（`openaiCompatibleProvider` 用 OpenAI Node SDK，按模型切 `baseURL`）：
  - Kimi/Moonshot：`https://api.moonshot.cn/v1`
  - DeepSeek：`https://api.deepseek.com`
  - 通义千问/DashScope：`https://dashscope.aliyuncs.com/compatible-mode/v1`
  - ⚠️ **Mimo（小米）无托管 OpenAI 兼容 API**，仅开源权重，需自托管 vLLM 后再套兼容壳，MVP 不纳入。
- **Guardrails**（已实现，复用）：真实 provider 双开关、每分钟频率、日调用上限、日预算、单次预计费用、超时、脱敏日志。
- **合规后置**：所有 LLM 产出经 `checkComplianceText()`，`block`/高风险拦截或回 `riskTips`。

### 6.3 腾讯数智人接口（我们的后端 wrapper，内部对接腾讯 IVH）

> 前端只调"我们的后端"；后端适配层内部调用腾讯。腾讯侧来自官方文档：环境 `https://gw.tvs.qq.com`，appkey + 签名（query 参数）；**具体参数与签名以腾讯官方 SDK 为准**。

**形象 / 资产**
| 我们的接口 | 用途 | 内部对接 |
|---|---|---|
| `GET /api/avatar/figures` | 列出租户可用腾讯形象 | 腾讯形象资产 |
| `POST /api/avatar/figures/clone` | 形象复刻接入（上传真人视频，异步） | 腾讯形象复刻，回 `taskId` |
| `GET /api/avatar/figures/clone/:taskId` | 查复刻进度 | 轮询，`status: cloning|ready` |

**开播 / 驱动 / 下播**
| 我们的接口 | 用途 | 内部对接腾讯（直播数智人） |
|---|---|---|
| `POST /api/live/sessions` | 开播 | `openliveroom`（入 `figureId, mode, platformPushUrl, productGroupId`） |
| `GET /api/live/sessions/:id` | 查状态（轮询直到就绪） | `getliveroom`（腾讯 `Status=2` → ready） |
| `POST /api/live/sessions/:id/speak` | **让数字人说/插播**（替代原"下发 speak 命令"） | `takeover`（**先过合规复检**，入 `text, tone?, action?, priority:insert|queue`） |
| `POST /api/live/sessions/:id/mode` | 实时 ↔ 预生成切换（hybrid） | 切换驱动模式 |
| `POST /api/live/sessions/:id/close` | 下播 | `closeliveroom` |

**实时状态（替代 PrintAdapter）**
- 腾讯视频流内嵌 **SEI 事件**：`SentenceStart / SentenceOver / AudioStart / AudioOver / text`。
- 后端消费 SEI → 经**我们的实时通道**（WebSocket/SSE）推给中控台，用于：当前播报、字幕同步、"播完"回执、队列推进。

**用量计量（计费源）**
- 后端在 `open`→`close` 期间按心跳累计每个 session 的**直播分钟 / 并发**，写 `usage_records`，驱动额度扣减、成本卡、账单。

### 6.4 最小真链路时序（端到端）

```
商家点[开播]
  → POST /api/live/sessions            (后端先合规检查首批话术)
  → 后端 openliveroom → 轮询 getliveroom 直到 Status=2
  → 返回就绪；推流到商家平台直播间(platformPushUrl)
  → 弹幕进来 → POST /api/ai/comment-reply (LLM+合规)
  → POST /api/live/sessions/:id/speak  (takeover, 合规复检) → 数字人开口
  → 腾讯流 SEI(SentenceStart/Over) → 后端 → WS → 中控台字幕/状态更新
  → 计量累加 (分钟/费用) → 首页额度卡实时减少
  → 商家点[下播] → closeliveroom → 结算本场用量
```

### 6.5 多租户 + 计费数据模型（关键表）

```
tenants(id, name, plan, status, created_at)
tenant_users(id, tenant_id, user_id, role)                 -- 管理员/员工
subscriptions(id, tenant_id, plan, period, quota_minutes, started_at, expires_at, status)
usage_records(id, tenant_id, session_id, type[tencent_live|llm], minutes|tokens, cost, occurred_at)
tencent_figures(id, tenant_id, figure_id, name, status[cloning|ready], source_video)
live_sessions(id, tenant_id, room_id, tencent_room_id, figure_id, mode,
              platform_push_url, status, started_at, ended_at, spent_amount)
```
- 现有业务表统一加 `tenant_id`（products / avatars / live_rooms / speech_queue …）。
- `compliance_keywords` 分两层：平台全局（`tenant_id=NULL`）+ 租户自定义。

## 8. 成本模型与定价约束（2026-06 实测）

> 价格来自腾讯云官方《智能数智人价格指南》(`cloud.tencent.com/document/product/1240/101944`) 与各 LLM 官方页，单位人民币。**价格会变，部分需商务确认。**

### 8.1 关键事实（纠正早期判断）

云渲染交互服务 = **按“并发路数”包月/包年（flat），不是按分钟**。一路 2D 数字人 3,500 元/月，24 小时随便播。**成本大头是数智人交互服务，不是 LLM。**

### 8.2 腾讯数智人价格

**交互服务（实时 A，云渲染，按并发“路”）**
| 形象 | 月付/路 | 年付/路 |
|---|---|---|
| 2D | 3,500 元 | 27,000 元（≈2,250/月） |
| 2D 高精 | 6,750 元 | 54,000 元 |
| 3D 半写实 | 5,200 元 | 41,000 元 |
| 3D 写实 | 6,750 元 | 54,000 元 |

**形象采购**：租赁 2D 通用口型 50 元/月（400/年）、2D 专属 125 元/月（1,000/年）；定制 2D 照片 19.9 元/个、2D 小样本 1,000–10,000 元/个、2D 精品（真人级）350,000 元/个；3D 租赁 18,800–37,500 元/月（贵，先不碰）。
**声音定制**：极速版 39.9 元/个；基础版 3,000–10,000 元/个。
**播报合成小时包（预生成 B，按“合成小时”）**：训练版 2D 小样本 ≈60–200 元/合成小时（600–2,000 元/10 小时包）；免训练视频 500 元/小时；免训练照片 2,500 元/小时。

### 8.3 LLM 价格（每百万 token，小头）

DeepSeek V4 Flash ≈¥1/¥2；V4 Pro ~$0.44/$0.87；Kimi K2.5 $0.60/$2.50；通义 Qwen-Flash $0.05–0.25/$0.40–2.00。一场直播 LLM 成本几元~几十元/天，相对数智人可忽略。

### 8.4 两条路成本（一个商家、一个直播间、长时段播）

| 路线 | 月成本/商家（独占一路） | 说明 |
|---|---|---|
| **A 实时 2D** | ≈ **3,600 元/月**（3,500 路 + 125 形象） | 包月，24h 随便播，真互动 |
| **B 预生成 2D** | ≈ **几百元/月**（10h 视频 600–2,000 近一次性 + 125 形象） | 循环播，假实时，平台风险 |

### 8.5 定价硬约束

独占一路成本底 ≈ **3,600 元/月/商家**，因此：
- ❌ 做不了 ¥99/月 的便宜工具（卖价必须 > 成本）。
- ✅ 三条出路：① **定位中高端**（月费数千元）；② **错峰复用/超卖路**（买 N 路服务更多错峰开播的商家，运营复杂、有并发风险）；③ **便宜档走 B + 高端档走 A**（hybrid，价格数据支持此结论）。

### 8.6 验证期建议（别一上来买企业大包）

先用**腾讯智影消费档**（数字人直播套餐千元级/月、播报会员 48–88 元/月）低成本跑通最小真链路；或买 **1 路 2D 实时（3,500 元/月）** 做技术验证，确认链路与体验后再扩。

## 9. 风险与前置确认（写代码前必须先定）

1. **成本账（最高）**：实时交互按“并发路”包月（2D ≈ 3,500 元/月/路），**非按分钟**——详见 §8 成本模型。独占一路成本底约 3,600 元/月/商家，**定价不能走低价路线**；hybrid（B 兜底）+ 错峰复用是关键缓解。
2. **弹幕合规接入**：抖音/快手/视频号/淘宝**无合法稳定的开源弹幕接入**，仅 B 站有官方开放平台。A 的实时互动落在这条路上，需官方/ISV 授权或承担封号风险。
3. **平台监管**：数字人/无人直播合规要求收紧（AI 标识、部分类目限制），SaaS 服务商替商家承担聚合风险。
4. **Mimo 无托管 API**：规划不依赖其密钥制接口。
