### 修订建议（结合“私有化买断优先”商业模式）

1. 私有化买断优先场景下，**首选评估方向调整为 硅基智能 HeyGem / DUIX 本地私有化方案**，而非 HeyGen / D-ID 海外 SaaS。理由：
   - 商业模式吻合：开源 + 免费商用 + 本地部署，无按分钟计费，避免 24 小时直播成本失控（SaaS 按 $1–6/分钟计，多直播间长时直播成本不可控）。
   - 架构吻合：已建成的“执行端客户端跑在直播电脑 + 接 OBS”架构，正好用于在本地 GPU 上驱动数字人引擎并输出到 OBS 虚拟摄像头。
   - 合规吻合：国内方案对抖音/快手/视频号推流和合规更友好，数据可不出本地。
2. **D-ID 作为对照基准**：以 1 天、小预算跑一次（实时文档最清晰、亚 0.5 秒延迟），用于给本地方案设定“质量/延迟应达到的水平”标尺，不作为上线方案。

### 定方案前必须人工核实的 3 件关键事项（离线 vs 实时分水岭）

1. **HeyGem 与 DUIX 的定位区别**：HeyGem 偏“快速生成数字人视频文件”，DUIX 才是“实时交互平台”。直播必须走实时链路（DUIX 方向），需确认其为连续实时流而非离线视频生成。
2. **本地 GPU 要求**：真人级实时渲染所需显卡/显存规格，决定每台直播电脑硬件成本。
3. **输出链路**：能否输出虚拟摄像头 / RTMP，供 OBS 捕获（对照已接好的 OBS 读取能力）。

## 0. 关键结论

我们的核心需求不是“生成一段数字人口播短视频”，而是：

```text
直播话术 / 人工接管文本
→ TTS / 声音克隆
→ 口型同步
→ 表情 / 肢体动作驱动
→ 连续视频流
→ OBS / 虚拟摄像头 / 直播推流
```

因此第一分水岭是：

| 能力 | 离线短视频 | 实时连续直播 |
| --- | --- | --- |
| 输入 | 一段文本或音频 | 不断到来的话术、弹幕回复、人工插队 |
| 输出 | MP4 / MOV 等文件 | 连续音视频流、WebRTC、RTMP、虚拟摄像头 |
| 延迟要求 | 分钟级可接受 | 秒级或更低，需稳定连续输出 |
| 中控联动 | 弱 | 强，需要可暂停、插队、审核、切回主线 |
| OBS 接入 | 播放文件即可 | 需要浏览器源、虚拟摄像头、RTMP/WebRTC 或本地执行端 |
| 适合场景 | 商品短视频、课程录播、素材预生成 | 直播带货、弹幕互动、人工接管、24 小时直播 |

初步建议：

1. 私有化买断优先：优先评估“混合方案”，即商业或授权模型提供形象 / 声音资产，本地执行端负责 TTS 编排、口型驱动、OBS 输出和风控链路。
2. 先 SaaS 验证：优先选择明确支持实时流的商业 API，而不是只支持短视频生成的数字人口播工具。
3. 开源自建适合做研发验证，不宜直接作为第一版商用直播底座，除非团队已经具备 GPU、实时渲染、音视频工程、授权和合规能力。
4. 短视频生成能力可以作为商品素材生产模块，但不能替代直播中控台的实时播报链路。

## 1. 评分规则

评分：1 = 弱 / 高风险，3 = 可验证但有明显工程成本，5 = 强 / 更适合当前需求。

## 3. “离线短视频”与“实时连续直播”的判断清单

如果一个方案只满足下面条件，它更像离线短视频工具：

- 输出 MP4 文件。
- 每次输入一段完整文本或音频。
- 生成耗时可以是几十秒到几分钟。
- 没有持续会话、插队、暂停、恢复、下一句话预览。
- 不能直接返回连续视频流。
- OBS 接入靠播放生成好的视频。

如果一个方案要支撑实时连续直播，至少需要满足：

- 支持实时输入文本或音频片段。
- 输出 WebRTC / RTMP / 视频帧流 / 可被 OBS 捕获的连续画面。
- 支持连续会话或长时间运行。
- 支持低延迟响应、队列、打断或插队。
- 能把 TTS、口型、表情、动作和字幕状态与中控台同步。
- 有商用授权、形象授权、声音授权和内容合规机制。

## 4. 推荐路线

### 4.1 私有化买断优先

推荐：混合方案优先。

建议路径：

1. 先采购或授权可商用的数字人形象和声音资产。
2. 本地执行端负责：
   - 接收云端中控台下发的待播话术。
   - 调用本地或私有化 TTS。
   - 驱动口型 / 表情 / 动作。
   - 输出到 OBS 虚拟摄像头、浏览器源或 RTMP。
3. 合规、延迟播控、人工接管、成本监控仍放在我们的后台系统中。

优点：

- 数据和直播链路更可控。
- 适合企业客户、政企、金融、品牌直播等私有化诉求。
- 长期可沉淀执行端能力，不完全被 SaaS 锁死。

缺点：

- 需要本地 GPU 或至少较强本地推理/渲染环境。
- 需要处理驱动模型、OBS、虚拟摄像头、音频同步和稳定性。
- 授权谈判复杂，尤其是真人形象、声音克隆和商用直播。

优先评估：

- 腾讯云智能数智人 / 云直播数字人：国内云和直播生态更近。
- 硅基智能 / Duix 私有化或 SDK 路线：重点核实买断、源代码、延迟、桌面端输出。
- NVIDIA Audio2Face / 3D 路线：如果产品愿意接受 3D 角色而非真人级 2D 数字人。

### 4.2 先 SaaS 后私有化

推荐：商业实时 Avatar API 做第一阶段验证。

建议路径：

1. 用 HeyGen / D-ID / 阿里云 AvatarDialog / 腾讯云数字人直播 API 做真实流式验证。
2. 我们只负责：
   - 文案生成。
   - 合规检查。
   - 待播队列。
   - 人工接管。
   - OBS 捕获或转推。
3. 记录每小时成本、延迟、崩溃率、并发上限和平台审核风险。
4. 再决定是否转私有化买断。

优点：

- 最快验证“中控台 → 数字人 → OBS”的商业闭环。
- 无需一开始买 GPU 或搭建模型。
- 可以用真实客户场景倒逼需求。

缺点：

- SaaS 成本和并发限制可能影响直播时长。
- API 可控性、稳定性、地域合规和内容审核规则由供应商决定。
- 供应商可能更适合互动客服，不一定适合带货直播的高频插队和商品节奏。

优先评估：

- D-ID / HeyGen：海外 API 文档清晰，适合技术验证。
- 腾讯云 / 阿里云：国内合规、直播推流和商务沟通更可控。

## 5. 最小验证实验设计

目标：用最低成本验证“文案 → TTS → 口型视频 → OBS 预览”是否跑通。

### 5.1 验证范围

只验证垂直链路，不做完整直播业务：

```text
输入一句商品话术
→ TTS 生成音频
→ 数字人口型同步生成画面
→ 输出到 OBS 预览
→ 人工观察口型、延迟、稳定性
```

### 5.2 两条实验路线

#### 路线 1：SaaS 实时流验证

候选：

- D-ID Agent Streams。
- HeyGen Interactive Avatar / Streaming API。
- 阿里云 AvatarDialog。
- 腾讯云数字人直播相关 API。

需要准备：

- 对应供应商账号。
- 一个可商用或测试授权的数字人形象。
- 一个 TTS / 声音配置。
- OBS。
- 本地浏览器源或 WebRTC/RTMP 转推工具。

预算：

- 账号、分钟数、API 调用价格均需人工核实。参考来源：HeyGen pricing、D-ID pricing、腾讯云 / 阿里云 API 文档；访问日期 2026-06-02。
- 建议先按 1 小时内测试预算申请，不要直接购买大额年费。

验收指标：

- 首帧时间：需人工记录。
- 单句从提交到开始播报延迟：需人工记录。
- 连续播报 30 分钟是否中断：需人工记录。
- OBS 预览是否稳定。
- 能否插入下一句话。
- 字幕和声音是否同步。

#### 路线 2：开源 / 本地验证

候选：

- Wav2Lip + 本地 TTS：低成本验证口型同步，但偏离线。
- SadTalker + 本地 TTS：低成本视觉 Demo，但不适合实时。
- GeneFace++ / Audio2Face：更接近实时，但需要 GPU 和工程能力。

需要准备：

- Windows 直播电脑。
- NVIDIA GPU，显存规格需按模型人工核实。
- Python / CUDA / FFmpeg。
- OBS。
- 一张授权头像或一段授权视频。
- 本地 TTS 或云 TTS。

预算：

- 开源模型本身可能免费，但 GPU、调试、工程人力和授权风险是真实成本。
- Wav2Lip / SadTalker / GeneFace++ 商用授权必须人工核实，不能默认可商用。

验收指标：

- 单句生成是否能低于直播可接受延迟。
- 是否能连续多句不卡顿。
- OBS 输出方式是否稳定。
- 口型、头动、表情是否可接受。
- 是否能在没有真人授权争议的素材上运行。

### 5.3 推荐最小实验顺序

1. 先用 SaaS 实时流做 1 天验证，证明“中控台话术 → 数字人流 → OBS”可行。
2. 同时用 Wav2Lip 或 SadTalker 做离线短视频对照，确认它们不能直接满足直播实时要求。
3. 如果 SaaS 成本过高，再进入私有化 / 混合方案谈判。
4. 如果必须买断，优先要求供应商提供：
   - 本地 SDK。
   - 可商用授权文件。
   - 虚拟摄像头或 RTMP 输出样例。
   - 直播连续运行压测报告。
   - 数据不出本地或私有云方案。

## 6. OBS / 推流接入方式对比

| 方式 | 适合方案 | 优点 | 风险 |
| --- | --- | --- | --- |
| OBS 浏览器源捕获 WebRTC 页面 | SaaS 实时 Avatar、Web 前端预览 | 接入快，适合 MVP | 浏览器崩溃、音频路由、跨域、画面比例和透明背景需要调试 |
| 虚拟摄像头 | 本地执行端、3D 引擎、OBS 二次捕获 | 直播伴侣容易识别为摄像头 | Windows 驱动、音画同步、分辨率、权限问题 |
| RTMP 推流到 OBS / 云直播 | 腾讯云 / 阿里云 / 本地 FFmpeg | 与直播链路接近 | 延迟、转码、断线恢复、推流鉴权 |
| NDI / Spout / Syphon | 本地渲染引擎 | 低延迟本地画面传输 | 平台兼容性和客户电脑环境复杂 |
| 直接 OBS 插件 | 深度私有化 | 控制力最强 | 研发和维护成本最高 |

OBS 官方资料显示其虚拟摄像头可将 OBS 输出作为摄像头源给其他应用使用；具体版本和平台差异需人工核实。来源：OBS Virtual Camera Guide，访问日期 2026-06-02。

## 7. 风险清单

### 7.1 技术风险

- SaaS 返回的是 WebRTC 流，但我们的直播平台需要 RTMP 或直播伴侣摄像头输入。
- 开源模型可以生成 demo，但无法稳定连续直播。
- 声音克隆和口型同步分别来自不同供应商时，延迟和节奏可能错位。
- 低延迟需要端到端优化，不是单个模型指标能决定。
- GPU 环境、驱动、CUDA、OBS 和音频设备会显著增加交付复杂度。

### 7.2 商业风险

- 按分钟或按小时计费可能让 24 小时直播成本失控。
- SaaS 供应商可能限制并发、时长、商业用途或行业。
- 私有化买断需要确认源代码、模型权属、更新服务和 SLA。
- 数字人形象、声音克隆、训练素材必须有授权链。

### 7.3 合规风险

- 未经授权克隆真人形象或声音可能引发肖像权、声音权益、人格权风险。
- 带货直播涉及价格、功效、绝对化表达、平台规则和广告法风险。
- 直播平台可能要求数字人标识或对无人直播有单独规则。
- 海外 SaaS 涉及数据出境、素材存储和供应商条款问题。

## 9. 建议下一步

1. 约供应商做 30 分钟技术澄清，重点问：
   - 是否输出连续实时流，而不是生成视频文件。
   - 是否能接 OBS / 虚拟摄像头 / RTMP。
   - 延迟、并发、单场时长、断线恢复。
   - 形象和声音授权方式。
   - 价格按分钟、小时、并发还是买断。
2. 做 1 个垂直切片实验：
   - 选择一个 SaaS 实时流方案。
   - 输入固定商品话术。
   - 输出到 OBS 预览。
   - 人工记录延迟、稳定性、口型质量。
3. 同时做 1 个开源离线对照：
   - Wav2Lip 或 SadTalker 生成 MP4。
   - 证明其适合短视频素材，不等价于直播实时输出。
4. 再决定是否进入“私有化买断谈判”或“先 SaaS 上线验证”。

## 10. 供应商（硅基智能 / DUIX）商务提问清单

> 用于 30 分钟技术 + 商务澄清。按“必答”优先级排序，先问完前 3 组再谈价格。

### A. 实时能力（生死线，必答）

1. 用于直播带货的是 HeyGem 还是 DUIX？它输出的是**连续实时流**还是**生成视频文件**？
2. 单句话术从“提交文本/音频”到“数字人开始播报”的端到端延迟是多少？
3. 能否连续运行 4 小时以上不中断？是否支持播报中**插队/打断/暂停/恢复**（直播带货高频需要）？
4. 是否支持**实时音频或文本片段输入**，而不是一次性整段输入？

### B. 输出与集成（必答）

5. 是否能输出到**虚拟摄像头 / RTMP / WebRTC / NDI**，让 OBS 捕获？有无样例？
6. 是否提供本地 **SDK / API**？运行平台（Windows？需要哪种 GPU、显存？）。
7. 能否在我们自有的“直播电脑执行端”进程内被调用驱动（而非必须用它们的整套客户端）？

### C. 授权与私有化（必答）

8. 免费商用的具体边界？“用户>10万 / 年营收>$1000万需商业许可”的口径、价格、签署方式？
9. **私有化买断**是否提供：本地 SDK、可商用授权文件、源代码边界、模型权属、更新服务、SLA？
10. 数字人**形象授权 / 声音克隆授权**如何处理？用客户自有真人形象/声音是否需要单独授权链与肖像声音同意书？

### D. 成本与稳定性

11. 私有化是一次性买断还是年费？按设备/并发/直播间如何计价？
12. 是否有**连续直播压测报告**（崩溃率、内存泄漏、长稳）？
13. 多直播间并发时单台 GPU 能带几路数字人？

### E. 合规

14. 是否内置/支持数字人标识、内容审核钩子？
15. 对“无人值守直播”是否有平台合规建议（部分平台对纯数字人直播有单独规则）？

### 决策红线

- 若只能生成视频文件、不能连续实时流 → 不适合做直播底座，只能当商品短视频素材模块。
- 若无法输出 OBS 可捕获的画面 → 与现有执行端 + OBS 架构不兼容。
- 若形象/声音授权链不清晰 → 带货直播有肖像权/声音权/广告法风险，不可上线。
