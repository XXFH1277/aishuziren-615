# 2026-06-02 后端安全收口交接

## 本次目标

完成后端上线红线级别的安全收口，不改前端业务逻辑，不引入新框架。

## 已完成内容

1. 全量 `/api` 鉴权
   - 除白名单外，所有 `/api` 路由，包括 `GET`，均必须通过 `requireAuth`。
   - 白名单仅保留：
     - `GET /api/health`
     - `POST /api/auth/login`
   - `/uploads` 静态资源行为保持不变。

2. 登录失败限流
   - 新增 SQLite 表：`auth_login_attempts`。
   - 按 `username + ip` 记录失败次数。
   - 5 分钟内失败 5 次后锁定 10 分钟。
   - 不引入 Redis 或新框架。

3. 默认密码加固
   - seed 默认密码不再硬编码。
   - 优先读取环境变量：`SEED_ADMIN_PASSWORD`。
   - 未设置时生成随机强密码，并仅在 `npm run server:seed` 输出中打印一次。
   - 不将随机密码写入仓库、文档、Mock 或 SQLite 明文字段。
   - `users` 表新增 `must_change_password` 字段。
   - seed 管理员 `admin` 首次登录后必须改密。

4. 改密接口
   - 新增：`POST /api/auth/change-password`。
   - 需要登录。
   - 校验旧密码。
   - 新密码使用现有 scrypt 工具重新哈希。
   - 改密成功后清除 `must_change_password`。

5. 错误信息脱敏
   - `server/index.js` 全局错误处理不再把 `error.message` 返回前端。
   - 前端只收到统一错误文案和错误码。
   - 详细错误仅 `console.error` 到服务端。

6. Smoke Test 增强
   - 覆盖未登录 `GET` 被拦截。
   - 覆盖登录失败限流锁定。
   - 覆盖强制改密和改密成功。
   - 后续 smoke 请求默认携带登录 token，适配全量 API 鉴权。
