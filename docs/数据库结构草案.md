# 数据库结构草案

Phase：11  
状态：设计草案，不创建数据库  
目标数据库：SQLite（Phase 12 预期）  

## 1. 设计原则

- 本文只描述后续数据库结构，不创建 `.db` 文件，不写迁移脚本。
- 表名使用 snake_case，字段名使用 snake_case，前端 API 返回时转换为 camelCase。
- 所有表建议包含：
  - `id TEXT PRIMARY KEY`
  - `created_at TEXT`
  - `updated_at TEXT`
  - `deleted_at TEXT NULL`
- 时间统一保存 ISO 8601 或 `YYYY-MM-DD HH:mm:ss`，前后端契约中再确定最终格式。
- JSON 型字段在 SQLite 中先用 `TEXT` 存 JSON 字符串，后续如切换 PostgreSQL 可迁移为 JSONB。
- API Key、模型密钥、平台密钥不进入前端，不建议明文进入 SQLite。后续应由后端读取环境变量或使用加密存储。

## 11. 关系草案

```text
product_groups 1 ---- n products
avatars 1 ---- n live_rooms
product_groups 1 ---- n live_rooms
live_rooms 1 ---- n live_tasks
live_tasks 1 ---- n comments
comments 1 ---- 0..1 questions
questions 1 ---- 0..1 speech_queue
live_tasks 1 ---- n speech_queue
executors 1 ---- n executor_heartbeats
executors 1 ---- n executor_obs_status
roles 1 ---- n users
roles 1 ---- n role_menu_permissions
roles 1 ---- n role_operation_permissions
```

## 12. Phase 12 建议

1. 先创建基础表：`products`、`product_groups`、`avatars`、`live_rooms`、`live_tasks`。

3. 最后创建管理类表：`ai_model_providers`、`prompt_templates`、`users`、`roles`、`operation_logs`。
4. 初期可以写种子数据脚本，把当前 `src/mock/*.js` 转成 SQLite seed。
