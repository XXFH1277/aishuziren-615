# 2026-06-05 待播队列真实下发链路交接

## 1. 本次目标

把“待播队列 / 延迟播控”从页面 Mock 操作升级为可验证的本地真实编排链路：

```text
已审核话术
→ 后端查找直播任务绑定执行端
→ 写入 speak 命令
→ 执行端 PrintAdapter 拉取并模拟播报
→ ack 回执
→ 后端回写 speech_queue 播报状态
→ 前端刷新展示
```

本次仍不接真实 DUIX、TTS、口型同步、推流、直播平台或 OBS 播报执行，只验证“中控队列 → 执行端播报命令 → 状态回写”的闭环。

## 2. 后端改动

### 2.1 speech_queue 状态字段

在 `speech_queue` 现有审核字段基础上补充播报链路字段：

- `broadcast_status`：未审核 / 待下发 / 下发中 / 已播报 / 失败 / 不播报
- `executor_command_id`：关联的执行端命令 ID
- `broadcast_result_json`：执行端回执详情
- `broadcast_error_message`：失败原因
- `broadcast_started_at`：播报开始时间
- `broadcast_finished_at`：播报结束时间

为兼容已有本地 SQLite，字段补齐逻辑放在 `server/db/database.js` 的 schema ensure 流程中。

### 2.2 新增/完善接口

本次新增或强化了以下延迟播控接口：

```text
POST /api/delay-control/queue/:id/approve
POST /api/delay-control/queue/:id/reject
POST /api/delay-control/queue/:id/insert
POST /api/delay-control/queue/:id/dispatch
POST /api/delay-control/queue/dispatch-next
GET  /api/delay-control/current
GET  /api/delay-control/queue
```

下发逻辑：

1. 找到 `speech_queue` 项。
2. 校验审核状态必须为已通过类状态。
3. 找到对应 `live_task`。
4. 读取 `live_task.executor_id`。
5. 校验执行端存在且状态为在线类状态。
6. 复用执行端命令机制创建 `command_type = speak`。
7. payload 写入 `speechQueueId / liveTaskId / liveRoomId / text / tone / source`。
8. 将队列项状态推进为 `下发中`。

### 2.3 ack 回写

执行端对 `speak` 命令回执时，后端会按 `payload.speechQueueId` 回写对应 `speech_queue`：

- 成功：`broadcast_status = 已播报`
- 失败：`broadcast_status = 失败`
- 处理中：`broadcast_status = 下发中`

同时保存回执 detail、失败原因、开始时间和结束时间。

## 3. 前端改动

### 3.1 待播队列页

`/delay-control/queue` 已显示真实队列播报状态，并提供：

- 顶部“下发下一条”
- 单条“下发播报”
- 审核通过 / 驳回
- 插队 / 删除 / 标记高风险
- 执行端命令 ID 展示
- 下发后自动刷新

### 3.2 当前播报页

`/delay-control/current` 增加队列状态视图：

- 当前下发中话术
- 下一条待下发话术
- 最近已播报话术

该页面仍不执行真实数字人播报，只展示本地队列状态。

### 3.3 Service

`src/services/delayControlService.js` 新增：

```text
dispatchSpeechItem(id, data)
dispatchNextSpeechItem(data)
```

继续复用统一 `request`，不直接 fetch。
