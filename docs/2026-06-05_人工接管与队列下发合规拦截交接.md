# 2026-06-05 人工接管与队列下发合规拦截交接

## 本次目标

给直播中控台人工接管“立即播报”和延迟播控待播队列下发增加合规检查，避免高风险话术绕过审核直接生成 `speak` 命令。

本次仍只使用现有本地 API、SQLite、PrintAdapter 链路，不接真实 DUIX、TTS、口型同步、OBS 推流或直播平台。

## 主要修改

### 1. 复用现有合规模块

- 复用 `POST /api/compliance/check` 背后的 `checkComplianceText()` 逻辑。
- 没有新建第二套词库。
- 新增合规工具函数：
  - `isComplianceBlockingResult(result)`
  - `buildComplianceRiskTips(result)`
  - `buildComplianceErrorDetail(result)`

### 2. 直播中控台人工接管直发拦截

接口：

```text
POST /api/live/control-room/manual-speech
deliveryMode = direct
```

处理规则：

- 直发前先执行合规检查。
- 命中高风险或 `block` 规则时：
  - 直接拒绝直发。
  - 不创建 `speak` 命令。
  - 不写入“已下发”状态。
  - 返回命中词、风险等级和建议。
- 命中低/中风险提示类规则时：
  - 允许下发。
  - 返回 `riskTips`。
  - 将 `risk_level` 写入对应 `speech_queue` 项。

### 3. 人工接管入队风险标记

接口：

```text
POST /api/live/control-room/manual-speech
deliveryMode = queue
```

处理规则：

- 入队前也执行合规检查。
- 高风险话术允许入队，但强制标记为：
  - `review_status = 高风险待人工`
  - `broadcast_status = 未审核`
- 低/中风险话术入队时写入风险等级，并返回 `riskTips`。

### 4. 待播队列下发前复检

接口：

```text
POST /api/delay-control/queue/:id/dispatch
POST /api/delay-control/queue/dispatch-next
```

处理规则：

- 下发瞬间再次执行合规复检。
- 高风险或 `block` 规则：
  - 阻止下发。
  - 不创建 `speak` 命令。
  - 队列项标记为：
    - `review_status = 高风险待人工`
    - `broadcast_status = 未审核`
  - 写入 `broadcast_error_message`。
- 低/中风险：
  - 允许下发。
  - 更新 `risk_level`。
  - 返回 `riskTips` 和合规日志 id。

### 5. 编码损坏修复

修复 `server/routes/liveControlRoom.js` 中高风险评论统计 SQL 的损坏字符：

```sql
risk_level NOT IN ('低', '无')
```

原损坏片段为：

```sql
risk_level NOT IN ('低', '浣?')
```

本次保持原统计语义：排除低风险和无风险，其余计入风险总览。

### 6. 前端提示

直播中控台人工接管区：

- 立即播报被合规拦截时弹出明确提示。
- 提示包含后端返回的命中词、风险等级和建议。
- 低/中风险放行时展示合规提示。
- 待播队列下发复检命中低/中风险时展示“合规复检提示”。
